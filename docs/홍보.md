# 홍보 (커뮤니티 · 디렉터리 · 스토어)

[검색등록.md](검색등록.md) 와 짝이 되는 문서다. 검색은 **천천히 쌓이는 쪽**,
여기는 **하루 반짝 몰리는 쪽** 이다. 둘의 성격이 다르니 기대도 다르게 잡아야 한다.

> 커뮤니티 글은 올린 날 하루 트래픽이고, 이틀이면 0 으로 돌아온다.
> 검색은 3주 뒤부터 매일 조금씩 들어오고 멈추지 않는다.
> **먼저 할 것은 검색 등록이다.** 아래 0번을 건너뛰고 커뮤니티부터 돌면,
> 애써 데려온 사람이 한 번 보고 사라진 뒤 다시 찾아올 길이 없다.

---

## 0. 먼저 — 아직 안 돼 있는 것

`wrangler.toml` 77~89 줄에서 두 줄이 **주석 그대로**다.

```toml
# GOOGLE_VERIFY = "google1a2b3c4d.html"
# NAVER_VERIFY  = "naver1a2b3c4d.html"
```

즉 사이트맵도 제출되지 않았고, 네이버·구글 어느 쪽에도 이 사이트는 등록돼 있지 않다.
무료 페이지 넷(`/tti`, `/calc/samjae`, `/calc/sinsal`, `/calc/bonmyeong`)은
**검색으로 들어오라고 만든 문**인데 지금은 문 앞에 길이 없는 셈이다.

20분이면 끝난다. [검색등록.md](검색등록.md) 를 그대로 따라가면 된다.
이것만 해 두면 아래 커뮤니티 글이 하루짜리로 끝나지 않는다.

## 1. 어디에 올릴 것인가

한 곳에 올릴 때마다 **그 커뮤니티의 자기홍보 규정을 먼저 읽는다.**
같은 글을 복사해 열 군데 돌리는 것이 가장 빨리 망하는 길이다 — 대부분 밴이고,
사주 앱은 한 번 "스팸" 으로 찍히면 되돌리기 어렵다.

### 국내 — 여기가 본진이다

| 곳 | 성격 | 자기홍보 |
|---|---|---|
| **디스콰이엇** disquiet.io | 한국 메이커 커뮤니티. 제품 공개가 곧 콘텐츠 | 환영 |
| **긱뉴스** news.hada.io | 개발자. "만든 것" 카테고리가 따로 있다 | 환영 |
| **오늘의 개발** / 개발자 뉴스레터 제보 | 기술 얘기가 있어야 실린다 | 제보 형태 |
| 네이버 블로그 (직접 운영) | 사주 검색어를 잡는 두 번째 통로 | 내 채널 |
| 인스타그램 · 스레드 | 운세는 이미지 궁합이 좋다. 카드 이미지가 이미 있다 | 내 채널 |
| 카카오 오픈채팅 (사주/타로 방) | 전환은 높지만 대부분 홍보 금지 | ⚠️ 규정 확인 |
| 디시 / 뽐뿌 / 클리앙 | **홍보 금지.** 올리지 말 것 | ✕ |

**앱인토스 미니앱(오늘운빨)은 이미 스토어 안에 있다.** 토스 안에서의 노출은
콘솔의 업데이트 문구와 아이콘·설명이 좌우한다 — 커뮤니티 글보다 그쪽을
다듬는 편이 유입이 크다. `mini/RELEASE-NOTES.md` 의 "업데이트 내용" 문단이 그 자리다.

### 해외 — 4개국어를 이미 지원하니 버릴 이유가 없다

| 곳 | 메모 |
|---|---|
| **Product Hunt** | 화요일~목요일 00:01 PST 등록. 하루 한 제품만 상위권에 남는다 |
| **Hacker News** (Show HN) | 사주가 아니라 **기술**이 후크다. 단일 파일 Worker, 절기 계산, 캐시 |
| **r/SideProject** | 관대하다. 만든 과정을 같이 쓸 것 |
| **r/Cloudflare**, **r/webdev** | 기술 얘기만. 앱 링크는 본문 끝에 한 줄 |
| Indie Hackers / Peerlist / Uneed / Fazier | Product Hunt 대안. 등록만 해 두면 백링크가 남는다 |
| r/tarot, r/astrology 계열 | ⚠️ 대부분 자기홍보 금지. 확인 없이 올리면 밴 |

> **제목**: 사주 앱을 혼자 만들어 운영합니다 — 웹 · 토스 미니앱 두 갈래로
>
> 명리학으로 사주를 계산하고, 그 결과를 AI 가 문장으로 풀어 주는 서비스를
> 1인으로 만들어 운영하고 있습니다.
>
> **웹**: https://myan.riger7070.workers.dev
> **토스**: 토스 앱에서 「오늘운빨」 검색
>
> 만들면서 어려웠던 것 몇 가지를 적어 둡니다.
>
> - **절기(節氣)를 반영한 사주 계산.** 사주는 달력의 월이 아니라 절기로
>   월주가 바뀝니다. 입춘 전에 태어난 사람은 전 해 생입니다. 이걸 직접
>   구현하면 반드시 틀리기 때문에 천문 계산 라이브러리에 맡겼습니다.
> - **날짜 경계.** 서버는 UTC 로 도는데 한국 사용자에게 "오늘"은 KST 입니다.
>   자정부터 오전 9시 사이에 접속한 사람에게 어제 기운을 보여 주던 버그를
>   잡느라 날짜를 만드는 자리를 전부 한 축으로 모았습니다.
> - **AI 비용.** 사용자 정보가 안 들어가는 풀이(타로·룬·띠운세 등)는 결과를
>   캐시해 두고 돌려 씁니다. 그냥 캐시만 하면 동시에 들어온 요청이 전부
>   비어 있는 캐시를 보고 전부 API 를 부르기 때문에, 진행 중인 요청을
>   묶어 주는 장치를 따로 뒀습니다.
>
> 백엔드는 Cloudflare Workers 한 파일, 프론트는 바닐라 JS 입니다.
> 프레임워크 없이 어디까지 가는지 보고 싶었는데 아직은 버티고 있습니다.
>
> 로그인 없이 볼 수 있는 것도 있습니다 — 오늘의 띠 순위, 삼재 계산기 같은 것들이라
> 궁금하시면 그것부터 눌러 보셔도 됩니다.

*긱뉴스는 더 짧게. 위에서 기술 세 덩어리만 남기고 서비스 소개를 두 줄로 줄인다.*

### Show HN (해외, 기술 후크)

> **Show HN: I built a Korean fortune-telling service on a single Cloudflare Worker**
>
> Saju (사주) is Korean four-pillars astrology: your birth moment maps to four
> pillars of the sexagenary cycle, and readings come from how those interact.
> I compute the chart deterministically, then use an LLM only for the prose.
>
> https://myan.riger7070.workers.dev
>
> Three things that were harder than expected:
>
> 1. **Solar terms.** Months don't turn on calendar boundaries — they turn on
>    the 24 solar terms, which are astronomical events. Someone born on Feb 3
>    may belong to the previous year. I delegate this to a library rather than
>    reimplementing ephemeris math.
> 2. **One timezone axis.** The Worker runs in UTC; users are in KST. "Today"
>    silently meant 09:00 KST for nine hours a day, so a cached daily reading
>    could be built on yesterday's element and served all day. Every date now
>    comes from one KST helper.
> 3. **Cache stampede on a paid API.** Readings with no user data are cached in
>    D1, but D1 is a network hop — five concurrent cold requests all miss and
>    all call the model. An in-isolate promise map collapses them to one call.
>
> Backend is one ~3k-line Worker file, no framework. Frontend is vanilla JS.
> Happy to answer anything about the astrology math or the Workers side.

*HN 은 자기 자랑을 싫어하고 구체적인 실패담을 좋아한다. 댓글이 붙으면 반드시 답할 것.*

## 3. 순서

하루에 다 하지 않는다. 반응을 보고 다음을 정한다.

1. **검색 등록** (0번) — 다른 무엇보다 먼저
2. 디스콰이엇 → 긱뉴스 (국내, 이틀 간격)
3. r/SideProject → Show HN (해외, 반응을 보고)
4. Product Hunt (위 세 곳에서 다듬어진 문구로, 화~목 등록)
5. 디렉터리 등록 (Peerlist, Uneed, Fazier — 백링크 목적, 급하지 않음)
6. 인스타·스레드는 위와 무관하게 꾸준히

## 4. 무엇을 보고 판단하나

커뮤니티 글의 성패는 **가입 수가 아니라 무료 페이지 체류**로 본다.
사주 앱은 첫 방문에 결제하지 않는다. 한 번 보고 좋았던 사람이
2주 뒤 검색으로 다시 들어오는 것이 정상 경로다.

한 달 뒤 서치콘솔의 "어떤 말로 검색해서 들어왔는지" 를 보는 것이
다음에 무엇을 만들지 정하는 가장 정확한 자료다 — 이건 검색등록.md 끝에도 적어 두었다.
